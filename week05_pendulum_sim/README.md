## 人机协同反思（思考手记）

### 1. 意图设计思考
在编写初始 Prompt 时，特意限制"单文件、不依赖外部库"，规避了 CDN 加载失败风险，确保双击即跑通 MVP。事后验证：这一约束让 AI 交付的每个版本都能直接验收，也让 Git 仓库里只有一份 HTML，回滚和对比极其干净。

### 2. 报错自愈思考
点击重置按钮报 `ReferenceError: resetAnimation is not defined` 时，把报错名称 + 精确行号 + 完整堆栈原样发给 AI。值得注意的是：AI 没有直接"猜着修"，而是先在仓库和 Git 历史中搜索符号定位报错来源，确认这是课程预设 bug 后重建演练页复现报错，再依次用 addEventListener 与 window 全局暴露两种方案修复验证——"先核实、再复现、后修复"比"快速修好"更能体现排错的工程价值。

### 3. 人机协同哲学反思
AI 承担了约 90% 的 Canvas 语法与数值积分代码编写，但人类主导了三件关键决策：**物理模型选择**（单摆简谐 → 双摆混沌的升级路线）、**视觉标准**（深色科技色 #1a1a24、辉光拖尾的验收口径）、**最终达标验收**（能量漂移、混沌初值敏感性等量化指标由人定义）。结论：AI 是执行引擎，人是定义验收标准的那只手。
